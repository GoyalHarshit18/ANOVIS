### 1. Persistence Architecture
The `RiskFusionResult` persistence happens directly inside `risk_fusion_service.py` (`run_risk_fusion_for_component`). The system natively uses SQLAlchemy to orchestrate writes. The `run_risk_fusion_for_run` wrapper oversees transaction boundaries via a `.flush()` call per-component (preserving iteration isolation in case of mid-run failures), followed by an overarching `.commit()` at the end of the batch run. In the event of an internal exception, a `.rollback()` fires on the current transaction. This preserves execution states smoothly without partial records.
